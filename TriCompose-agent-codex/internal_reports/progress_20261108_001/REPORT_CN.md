## 一 一句话概括与研究动机

**在当前留出队列与自动评测协议下，实验显示：在真实 EHR 与胸片配对数据上训练条件通路，可以明显改善给定 EHR 后生成胸片的人口学和部分病灶表现，并改善与生成报告构成的联合分布；目前更有依据的贡献是这种训练和配套 benchmark，而不是 EHR token 架构本身，也不是已经有效的 Agent。**【C1、C2、C2T、P3、P3b】

这里的三个模态分别是：结构化电子病历 EHR、胸部 X 光片 CXR，以及描述胸片的放射学报告。所谓“队列生成”，不是只生成一张看起来像胸片的图，而是希望一批生成结果满足用户指定的人群与疾病条件，并且病历、图像和报告之间的关系合理。

这件事需要同时回答三个问题：输入条件有没有进入图像；报告有没有合理描述图像；整批生成数据与真实数据的分布关系是否接近。一个模型即使能画出很明显的病灶，也可能把病灶画得过于典型，或者把阴性病例画得过于干净。单独问“有没有画出疾病”，会漏掉这些问题。【V8、V10】

项目因此有两条相互支撑的主线：

- **生成方法**：把 EHR 转成图像条件，训练这一条件通路，再用已有报告模型生成报告。
- **TriBench 评测**：分别检查可控性、评分器可靠性、病灶表现校准、联合分布、下游用途及记忆化风险，而不是把所有东西压成一个总分。

必须区分目标和当前完成范围：主要方法实验使用的仍是留出真实 EHR；早期试验与用户规格试验使用的是人工构造的简化 EHR。真实、复杂且完整的 synthetic EHR 分布生成尚未完成，因此现在不能宣称已经完成“从零生成完整、临床可靠的 synthetic patient”。【P1、C1、C2、G1】

## 二 整体框架与数据边界

### 生成链路

下面是文字示意，不包含任何图像或病例示例。

```text
队列条件或结构化 EHR
        │
        ├─ 规则文本化 → EHR-derived text
        │                    │
        └─ 数值与缺失状态编码 → EHR tokens
                             │
                   条件化胸片生成模型
                   C1：tokens
                   C2：text + tokens
                   C2T：训练后的 text-only
                             │
                        synthetic CXR
                             │
          MAIRA-2 + 该病例自身的 EHR indication
                             │
                      synthetic report
                             │
             单模态检查与跨模态联合分布评测
```

生成模型以 CheXGenBench 的 PixArt-Sigma 为起点。C1 训练 EHR encoder 与生成器的交叉注意力层；C2 继续训练文本与 token 的混合条件；C2T 只训练文本条件下的交叉注意力层。报告模型与用于评测的读片器在这些生成实验中保持冻结。因此，当前方案**不是“所有模型始终冻结、完全不训练”**。【C1、C2、C2T docstring】

C1 的 EHR 输入包含 14 个字段：年龄、性别、若干诊断和设备标志，以及 WBC、BNP、血氧、呼吸频率等检验或生命体征。每个字段有自己的身份编码，数值经过标准化，缺失值使用单独的可学习表示。缺失与正常是不同状态，不应默认把缺失写成“没有疾病”。【C1 docstring】

最新 G1T 进一步支持把训练后的纯文本 C2T 作为更简单的默认路线；C2 token 混合路线保留作比较和可选组件。这个默认选择不等于已经补齐完整 synthetic EHR、所有诊断控制或用户规格验证。【G1T、C2T】

不过，输入了某个字段，不等于已经证明图像会忠实反映它。目前重点证据集中在人口学、积液与设备等属性；尚无证据表明所有 labs、vitals 都具有可验证且必要的图像控制作用。【C1、C2、C2T、V4、V4b】

### Benchmark 的各个模块

评测链路不是“让一个模型给总分”，而是：先认证读片器，再测条件控制；同时检查图像风格转移是否改变读片结果，连续分数是否偏离真实参考，最后检查报告、联合分布与下游用途。【BENCHMARK_PLAN、V1、V8、V10、P3、P3b、V5、V5b】

图像端由 T1 或 F1c 输出属性分数；报告端由 CheXbert 抽取 finding 标签。EHR、图像与报告只比较可共同表达的内容。诊断记录没有某个 finding，不一定等于胸片上没有该 finding；CHF 也只是部分实验中水肿的代理，不能视为逐片等价关系。【P3 docstring；TRIBENCH_SPEC】

### 阅读指标的简明说明

| 指标 | 通俗含义 | 本项目的解释边界 |
| --- | --- | --- |
| 准确率 | 按固定规则分类后，多少比例与请求或参考标签相符 | 是自动读片结果，不是医生逐图确认 |
| 敏感度 / 特异度 | 真阳性中认出多少 / 真阴性中正确排除多少 | 两者要一起看，不能靠总报阳性获得好评 |
| AUROC | 不固定单个阈值，衡量分数能否把阳性排在阴性前面 | 条件 AUROC 高不保证真实感或表现强度合理 |
| MAE / 年龄相关 r | 平均年龄误差 / 年龄变化趋势是否一起变化 | 相关高也可能整体偏老或把年龄范围压窄 |
| κ | 扣除按边际比例偶然一致后的一致性 | 高于真实关系的一致性不必然更好 |
| 区间与配对差 | 显示估计值或同一病例上方法差异的不确定性 | 差值区间跨零，不等于证明方法等效 |
| TV 与联合保真度 | 两个概率分布差多少；以 1−TV 表达接近程度 | 不是逐例三模态全部正确率 |

这些是下文实验指标的阅读说明，不是新增测量结果。【C1、T1、P3、P3b docstring；TRIBENCH_SPEC】

## 三 方法如何演进及每一步留下的问题

### 方案 A 规则文本桥接

方案 A 把 EHR 中的信息写成接近放射学描述的文字，再交给已有图像生成模型。它的优点是接口简单、不需要新的 EHR encoder；缺点是已有模型是否理解这些提示、是否学过人口学条件，并没有保证。

早期 Sana 试验能够明显响应积液和水肿请求，但人口学控制弱，设备表现也不足。P1 中性别准确率为 0.52，年龄段准确率为 0.37；这些数字描述的是该设置，不是所有文本生成器的能力上限。【P1】

尤其需要区分：**P1 的桥接生图使用 Sana；C1/C2/C2T 的 BRIDGE 使用基础 PixArt-Sigma。** 二者不是同一图像生成器，不能把它们当作完全相同的对照。【P1、C1、C2T docstring】

### C1 直接输入 EHR tokens

C1 用结构化字段的数值和缺失状态生成 tokens，追加到固定文字的编码后，训练 EHR encoder 和交叉注意力。训练为 4,000 步；其主要规则是性别准确率至少 0.80、年龄段准确率至少 0.50。【C1 docstring】

C1 通过了这个绝对门槛，且相对 BRIDGE 的配对区间支持人口学改善。但积液表现弱，说明人口学控制的成功没有自动带来全部病灶控制的成功。【C1 结果】

### C2 混合文字与 tokens

C2 从 C1 权重继续训练，把同一 EHR 生成的规则文本与 EHR tokens 一起输入。动机是保留 C1 的人口学控制，同时用文本通路补足病灶。新增训练为 2,000 步；规则增加积液与设备 AUROC 均至少 0.75。【C2 docstring】

C2 通过预设规则，积液较 C1 明显改善，人口学控制也保留。它是当前主要的混合条件模型，但后续消融改变了我们对“为什么有效”的解释。【C2、C2T】

### C2T 公平得多的纯文本训练消融

C2T 不是再次拿未经训练的 BRIDGE 作对照，而是从基础模型出发，在同一真实 EHR-derived text 与胸片配对上训练文本通路。训练总步数为 6,000，匹配 C1 与 C2 的累计优化步数；没有结构化 tokens。【C2T docstring】

这项消融非常关键：它把“结构化表示是否必要”和“是否在真实配对上训练过”尽量拆开。结果并不支持 token 是人口学增益的必要来源。训练步数虽匹配，初始化、训练过程与采样顺序仍不同，因此也不能称为所有因素完全相同的严格等价试验。【C2T docstring、C2T 结果】

### 新完成 G1T 稀疏规格也没有支持 token 优势

G1T 让训练后的纯文本 C2T 使用同一批用户规格与种子，专门检验 token 是否更善于处理不完整输入。预声明 `TOKENS_HELP_SPECS` 要求：在 MINIMAL 条件下，C2 在性别准确率、较低的积液非请求阳性率或设备请求阳性率中，至少一项比 C2T 好超过 0.05。这是点指标判定，不能改称差异显著性检验。【G1T docstring】

| MINIMAL 规格指标 | C2 混合模型 | C2T 训练纯文本 | 来源 |
| --- | --- | --- | --- |
| 性别准确率 | 0.89 | 0.95 | G1T |
| 积液非请求阳性率，低为优 | 0.28 | 0.28 | G1T |
| 设备请求阳性率 | 0.64 | 0.64 | G1T |
| 请求 30 岁时的预测年龄 | 约 47–51 岁，G1 两种规格范围 | 35.4 岁 | G1、G1T |

`TOKENS_HELP_SPECS` 不成立。纯文本在人口学上更好，也显著减轻年轻端的压缩；当前可以优先采用更简单的 C2T。但非请求积液率仍为 0.28，不能把“选出更好的默认模型”说成“所有规格要求已满足”。未请求也不必然等于临床上明确阴性；这里保留实验规定的控制指标，不把全部非请求阳性直接称作幻觉。【G1T；G1 规则】

另一个重要诊断是：C2T 的 FULL 与 MINIMAL 输入文本完全相同，因为现有 `bridge_text` 只写阳性。C2 在 FULL 明确阴性规格下的积液非请求阳性率为 0.15 [0.10, 0.22]，C2T 为 0.28 [0.21, 0.36]；这暴露的是当前文本模板忽略明确阴性的限制，不能据此宣称“文本表达不了阴性”或“token 必然更好”。后续应先对齐相同的已知事实与缺失语义，再做公平比较。【G1T】

## 四 Benchmark 目前已经检验了什么

### 评判器资格 先确认尺子能不能用

评判器相当于自动读片的“尺子”。项目先在官方真实测试图及其放射科标签上检查它，再用于生成图，避免拿一个本来就读不准的模型给生成结果下结论。【E1、F1、F1c、T1】

预设资格为：finding 敏感度至少 0.60、特异度至少 0.80，真实参考阳性与阴性各至少 10 例；性别 AUROC 至少 0.95；年龄 MAE 不高于 8 岁且年龄段 macro-F1 至少 0.60。【F1c、T1、T1v3 docstring】

| 主要测量属性 | 当前主要读片器 | 原始真实测试表现 | 边界 | 来源 |
| --- | --- | --- | --- | --- |
| 性别 | T1 | AUROC 0.995 | 排序能力好，不代表合成域阈值完全校准 | T1 |
| 年龄 | T1 | MAE 6.58 岁；年龄段 macro-F1 0.704 | 继承年龄删失代理的限制 | T1 |
| 积液 | F1c | 敏感度 / 特异度 0.795 / 0.806 | PixArt 分辨率转移后需降级解释 | F1c、V1 |
| 水肿 | T1 | 0.740 / 0.807 | 相对较稳定；仍是自动标签测量 | T1、T1v3 |
| 设备 | T1 | 0.765 / 0.800 | 特异度恰在门槛，比较脆弱 | T1 |
| 肺炎 | T1 | 0.609 / 0.829 | 敏感度接近门槛，且诊断与影像不逐例等价 | T1、P3 |

F1c 和 T1 各自都没有通过“单个模型至少覆盖四个合格 finding”的原门槛。现在的实际做法是按属性使用不同读片头，不能把原先的失败改写为全部认证成功。【F1c、T1、BENCHMARK_PLAN】

T1v3 的性别 AUROC 为 0.998，年龄 MAE 为 5.97 岁、年龄段 F1 为 0.72，但其 finding 中仅水肿过线；因此没有替换预先使用的 T1。它提醒我们：肺炎和设备的通过状态会随训练和阈值漂移而翻转，不能只报“合格”而隐藏压线程度。【T1v3】

这些资格来自现有放射科标签，并非新的医生对每张生成图进行了盲读。相同测试队列被多次用于评判器开发与后续分析，这一点也需要披露。【E1、T1v3、V1、TRIBENCH_SPEC】

### V1 评分器能否跨过生成器的编解码风格

V1 把真实图像通过生成器的图像编解码器，再看原有标签还能否被读片器识别。它主要检查“生成器纹理会不会把尺子弄坏”，不是直接证明完全生成图上的判断准确。【V1 docstring】

Sana 编解码路线下，P1 等实验主要使用的读片头仍过线，调用翻转约为 1%–6%。但 PixArt 路线下，F1c 积液约为 0.81 / 0.78，T1 设备约为 0.79 / 0.77，未达到特异度 0.80 的门槛；对应裁剪对照已出现类似退化，提示分辨率是重要因素。C1/C2 的人口学主指标相对更稳健，而这些 finding 指标应作为有读片器限制的次要证据。【V1】

### R2 用已知读片误差重看阳性率

R2 使用已有的 Rogan–Gladen 校正：

```text
校正阳性率 = (观测阳性率 + 特异度 - 1) / (敏感度 + 特异度 - 1)
```

它试图区分“生成器真的画出了某个 finding”和“读片器本身误报”。公式是既有统计方法，不是项目发明。R2 在看到前序结果后设计，是明确的事后稳健性分析；其解释依赖真实编解码参考域的误差能迁移到生成域，不能直接称为真实患病率。【R2 docstring；CLAIMS】

R2 保留了积液、水肿的主要控制结论，也保留了某些否定措辞失效的结果；但一些早先被称为“未要求也生成”的设备或水肿现象，区间包含了可由读片器误报解释的范围，必须撤回相应强结论。例如设备在无目标组合中的观测阳性率 0.31，经校正约为 0.22，区间为 [0, 0.65]，不能据此确认生成器真的添加了设备。【R2】

### V8 与 V10 二值成功之外的夸张度和干净度

**CPI** 把生成阳性图的读片分数，放进真实阳性图的分数分布，看它通常位于什么百分位；**NCI** 则对照真实阴性分数。这里“真实阴性”是某个 finding 阴性，不等于整张片或整个人完全健康。【V8、V10】

按这些指标的操作定义，中心参考为 0.5。CPI 很高提示生成阳性更容易被读片器识别；NCI 很低提示生成阴性比真实阴性更“干净”。它们测的是**读片器分数的相对位置**，不是医生标注的病灶体积、临床严重程度或全部图像质量。【V8、V10 docstring】

| V8 Sana 指标 | 积液 | 水肿主读片器 | 解释 | 来源 |
| --- | --- | --- | --- | --- |
| 标准阳性提示 CPI | 0.88 [0.81, 0.94] | 0.97 [0.93, 0.99] | 按规则支持 CARICATURE | V8 |
| 阴性提示 NCI | 0.09 [0.06, 0.12] | 0.10 [0.07, 0.13] | 按规则支持 OVER_CLEAN | V8 |
| mild/small 提示 CPI | 0.80 [0.63, 0.94] | 0.92 [0.86, 0.97] | 仍未落到参考中心，MILD_REALISTIC 不成立 | V8 |

严重度词也没有在主要读片器上可靠地产生预设的连续变化。次级 F1c 水肿读片器有小幅正差，但不能替代主读片器的判定。换言之，“small”或“mild”并不能保证生成的是符合真实分布的轻症表现。【V8】

V10 改为使用**同一批 EHR 对应的真实胸片**作为参考，避免把不同队列的数值直接相减。

| V10 属性 | BRIDGE CPI / NCI | C1 CPI / NCI | C2 CPI / NCI | 主要结论 | 来源 |
| --- | --- | --- | --- | --- | --- |

| 设备 | 0.14 / 0.18 | 0.39 / 0.30 | 0.48 [0.41, 0.56] / 0.46 [0.39, 0.52] | 按项目规则满足 HYBRID_CALIBRATED | V10 |
| 预测年龄分布 KS 距离 | 0.50 | 0.10 | 0.09 | C1、C2 满足 KS 小于 0.15 的记录规则 | V10 |

积液 CPI 的 BRIDGE−C2 差约为 0.23，配对区间 [0.14, 0.34]，支持同一队列下的“减轻夸张”；但 C2 的积液阳性仍没有达到项目校准中心。设备改善主要是从欠表现走向参考中心，不应把所有属性统一叙述成“减少夸张”。【V10】

两点解释边界很重要：平均百分位接近中心不保证整个分布相等；区间包含 0.5 也不是正式的等效性检验。V8 与 V10 的参考人群和阳性定义不同，不能把 Sana 的 0.88 和 C2 的 0.74 直接当作严格配对的改善量。【V8、V10 docstring】

| 年龄请求 30 与 80 | 预测差 33.5 岁 [31.6, 35.5] | 32.9 岁 [31.1, 34.5] | 年轻端仍被压缩；不等于精确复制请求年龄 | V4、V4b |

### C15 与 M2 记忆化筛查

方法是把生成图与训练图的冻结 XRV 特征比较，再用真实验证图到训练库的最近邻相似度作为基线。训练库为重建的 80,000 张选定训练图；其真实验证最近邻余弦相似度的第 99 百分位为 0.9734。C1 与 C2 各筛查 240 张实验输出，超过阈值的均为 0 张，M2 还复现了 C1 筛查结果。【C15/C1NN、M2】

这支持“本次特征空间筛查没有发现异常接近训练图的样本”，不支持“绝无记忆化”或“可以无条件对外发布”。筛查不是 membership inference、差分隐私或法律/PI 审批；它也没有自动覆盖以后生成的全部下游或用户规格图像。【M2 docstring；C15 结果】

### V5 与 V5b 生成数据有没有实际用途

下游实验冻结 RAD-DINO 图像特征，训练简单分类探针，再在真实图上测试。主要终点是官方验证集，放射科标签测试集为次要终点；两者标签来源不同，不能挑更好看的测试集结果替代预设主要判定。【V5、V5b docstring】

V5 使用 Sana 的提示生成数据。其“少样本普遍有益”规则要求至少两个 finding 同时在真实样本预算为 50 与 200 时获益，实际只有积液满足，所以总体主张不成立。设备数据反而有害；只用合成图训练时，最差子组 AUROC 约为 0.44–0.48。提示词中把人群写得平衡，并不保证生成图或下游性能真的平衡。【V5】

V5b 用相同训练 EHR 与种子，比较 C2 图和未训练 BRIDGE 图：

| V5b 主验证指标 | BRIDGE 合成数据训练 | C2 合成数据训练 | 配对差的 95% 区间 | 来源 |
| --- | --- | --- | --- | --- |
| 设备 AUROC | 0.619 | 0.766 | +0.147 [0.114, 0.183] | V5b |
| 设备最差性别与年龄子组 AUROC | 0.58 | 0.71 | +0.130 [0.047, 0.203] | V5b |
| 积液 AUROC | 0.652 | 0.677 | +0.024 [-0.011, 0.060] | V5b |

因此，V5b 按原规则成立的是**至少有一个 finding 更有用、至少有一个 finding 的最差子组更好**，实际主要由设备支撑。不能把它写成全部 finding 都改善，或模型已达到临床公平性。【V5b docstring、V5b 结果】

增广真实训练数据时，C2 在真实预算为 50 的设备任务上带来约 +0.039 的 AUROC 差，区间 [0.016, 0.063]；但积液增广在主验证集略有害。EHR 诊断码不是逐图精确标签，是需要考虑的噪声来源；目前没有证明所有下游任务都受益。【V5b】

### P2 报告模型选择与 P3 三模态联合

P2 在固定生成图上比较报告路径。积液提及率从 CXRMate 的 0.31 升至 MAIRA-2 图像单独输入的 1.00；水肿从 0.15 升至约 0.42。加入本病例 EHR indication 后，水肿约为 0.52，但 normality-prompt 对照中的水肿提及也由 0 升至约 0.06。它支持报告路径会影响链路结果，而不是“加 EHR 文本永远有益”。【P2】

错配 indication 条件下，额外文本目标的提及率为 0.056，对应无 indication 基线为 0。这个结果可以称为本设置中“额外文字条件的跟随较低”，但不能据此证明全面抗幻觉：图像没有被要求生成该 finding，不代表像素中已被独立确认没有该 finding。【P2；TRIBENCH_SPEC、CLAIMS】

P3/P3b 不再只看单个模态的阳性率，而是统计同一病例的三个二值读片变量：EHR 标志、图像读片器标签、报告标签。它们构成八种可能组合，再与真实配对数据的组合分布比较。【P3、P3b docstring】

```text
TV = 两个联合分布各格概率差的绝对值之和 / 2
联合保真度 = 1 - TV
dTV = 方法的 TV - BRIDGE 的 TV
```

因此，dTV 为负表示比 BRIDGE 更接近真实联合分布。**联合保真度 0.91 不是“91% 的病例三种模态完全一致”。** 它也不是病理正确率；真实数据中的不一致、遗漏和读片误差本身会进入参考分布。【P3、P3b】

| finding | 真实图＋MAIRA-2 参照 | C1 联合保真度 | C2 联合保真度 | BRIDGE | C2−BRIDGE dTV 及 95% 区间 | 来源 |
| --- | --- | --- | --- | --- | --- | --- |
| 积液 | 0.92 | 0.90 | 0.91 | 0.76 | -0.15 [-0.18, -0.06] | P3、P3b |
| 设备 | 0.95 | 0.76 | 0.85 | 0.48 | -0.36 [-0.43, -0.27] | P3、P3b |
| 肺炎 | 0.95 | 0.80 | 0.81 | 0.84 | +0.03 [-0.05, +0.09] | P3、P3b |

P3 的 C1 与 P3b 的 C2 都按原规则在三个主要 finding 中至少两个优于 BRIDGE，因此各自预声明主张成立；肺炎未显示优势。真实图＋机器报告是一个操作性参照，不是数学上的最高上限。【P3、P3b】

还有一个不能回避的现象：C2 的 EHR–图像积液 κ 为 0.55，而真实数据约为 0.37。生成数据可能比现实更整齐、更一致；这不自动更好，反而可能掩盖真实临床关系中的复杂性，与残余积液 CPI 偏高的现象一致。【P3b、V10】

### V9 外部 RoentGen-v2 纠正了早期的概括

V9 按官方路径使用微调后的文本编码器、分词器及采样设置，把外部 RoentGen-v2 当作 benchmark 的被测对象，而不是我们的 EHR 生成方法。【V9 docstring、V9 结果】

| V9 指标 | RoentGen-v2 结果 | 原规则判定或解释 | 来源 |

| 请求积液、水肿、设备的阳性率 | 0.44 / 0.71 / 0.00 | 不是所有 finding 都可控 | V9 |

### M3 与传统图像分布指标的关系

M3 在 RAD-DINO 特征空间计算 Fréchet distance，属于 FID 类指标。已记录的点估计如下；它们不能和早期 F4 的 XRV-FID 数字直接比较。【M3、F4】

| 数据组 | 已记录 RAD-DINO FD 点估计 | 来源 |
| --- | --- | --- |
| 真实训练池对真实验证参照 | 52.9 | M3 |
| C2 | 85.5 | M3 |
| BRIDGE | 131.7 | M3 |
| Sana 严重度提示组 | 137.7 | M3 |
| Sana 标准提示组 | 152.7 | M3 |

`FD_MISSES_CONTROLLABILITY` 不成立：FD 在这次比较中也把 C2 排在 BRIDGE 前面，不能说“传统 FD 完全看不到改进”。但 `FD_BLIND_TO_PAIRING` 成立：只把 EHR 与图像错拼，图像集合没有改变，FD 不变；S1 的条件指标却明显下降。【M3、S1】

所以二者是互补关系：FD 衡量图像集合分布，条件指标衡量它与 EHR 的对应关系，CPI/NCI 给出具体属性的偏移诊断。M3 已披露原有有放回重采样抬高 FD 区间的问题；本报告不引用那些旧区间作显著性证据。【M3】

新完成的 M3 v2 已改用无放回子抽样。README 记录的区间为：真实基线 52.9 [51.6, 54.5]，C2 85.5 [83.9, 87.2]，BRIDGE 131.7 [129.5, 134.4]；BRIDGE−C2 为 46.2 [44.1, 48.9]。排序和配对盲区结论没有改变。这里准确称为**该无放回重采样协议记录的区间**：不沿用旧 bootstrap 口径，也不因去掉重复样本，就宣称已经独立验证了区间覆盖率或跨样本量可比性。正式发表前应固定 FD 的样本数与区间定义。【M3 v2 结果；M3 docstring】

## 五 目前最可支持的贡献定位

以下是有实验支撑的贡献方向，不是“世界首次”或已经排除全部相关工作的断言。Rogan–Gladen、百分位统计、Fréchet distance、重生成与条件训练本身均不应单独包装成新发明。【CLAIMS；BENCHMARK_PLAN】

| 贡献方向 | 已有支持 | 与已有工作的区别及边界 |
| --- | --- | --- |
| 以真实 EHR 配对为基础的队列条件生成及诚实消融 | C1/C2 有效，C2T 纠正了 token 解释 | 相比只拿已有文本生成器直接接 prompt，训练条件通路能改善本队列；但 RoentGen-v2 已有训练过的人口学文本条件，不能声称首次条件训练或 token 普遍优越 |
| 把三模态依赖关系作为评测对象 | P3/P3b 比较 EHR、图像读片、报告标签的联合分布 | RoentGen-v2 的图像生成与 MAIRA-2 的报告生成不是同一评测任务；这里复用它们的能力，不声称发明报告模型或首次进行 EHR 信息融合 |
| 在二值控制之外揭示病灶表现的分布偏移 | V8、V10、V9 区分夸张、欠表现和过度干净 | 补充 CheXGenBench 等图像真实性指标；贡献应落在问题定义、参考协议与验证，而非统计公式的首创 |
| 对 benchmark 自己做转移、干预与用途验证 | V1、R2、V4/V4b、S1、V5/V5b、M3 | 不把自动评分当金标准；显示哪些结论对读片误差、分辨率、配对关系和下游任务成立，哪些不成立 |

其中最稳妥的主线是：**真实配对训练改善可控生成，而分层 benchmark 发现二值“成功”与真实分布、三模态依赖和下游用途并不等价。**【C2、C2T、V8、V10、P3b、V5b】

Agent 应当作为待验证的扩展，而不是当前已证明的主要创新。早期 AG1 的 Agent 与固定路线终点率同为 0.152；AG3 探索性分析也未建立优于固定 Sana 路线的确认性证据。当前允许资料没有新的、预算匹配且评价独立的修复增益结果。【AG1、AG2、AG3x；CLAIMS】

## 六 成立的结论与必须撤回或保留的结论

### 可以作为当前进展汇报的结论

- 在本次留出 EHR 实验中，经过训练的 C1/C2/C2T 相比未训练 BRIDGE，人口学指标明显改善；C2 同时保留了较好的积液与设备相关表现。【C1、C2、C2T】
- C2 的主要人口学和积液增益不需要 token 架构才能获得；训练后的纯文本是必须保留的强基线。【C2T】
- 同一套用户规格下，G1T 也未支持 token 优势，训练纯文本 C2T 是当前更简单的默认；不过明确阴性仍被模板忽略，不能宣称规格控制已完成。【G1T】
- 只看二值 finding 阳性率会忽略评分分布的偏移，配对校准能提供额外诊断。【V8、V10】
- C1/C2 的三模态代理联合分布，在积液与设备上比未训练文本路线更接近真实参考。【P3、P3b】
- 下游用途随 finding 而变；设备任务有正向结果，积液没有相同证据。【V5、V5b】
- 当前读片器在噪声和部分分辨率变化下有明显局限，benchmark 必须把这种测量风险纳入解释。【V1、S1】

### 必须撤回、缩小或暂不主张的说法

| 说法 | 当前处理 | 依据 |
| --- | --- | --- |
| EHR tokens 是人口学改善的主要或必要原因 | 撤回；改为真实配对训练有效，tokens 为可选组件 | C2T |
| 文本或冻结模型无法控制人口学 | 撤回普遍表述，只限早期具体设置 | V9；C2T |
| 所有生成器都把病灶画得夸张 | 撤回；RoentGen-v2 也可能欠表现 | V9 |
| 高 κ 或高三模态一致性一定更真实 | 不成立；还要比较真实依赖关系与表现强度 | P3b、V10 |
| 所有未要求的阳性都叫泄漏或幻觉 | 不成立；须检查明确否定、像素证据与读片误报 | R2、P2 |
| 合成增广普遍改善下游 | 不成立；存在无益和有害结果 | V5、V5b |
| 记忆筛查通过等于隐私安全或许可公开 | 不成立 | C15、M2 |

## 七 局限与风险

### 自动读片并非生成图的临床金标准

部分头压线，部分在 PixArt 低分辨率变换后未过线，噪声又会显著损害预测。相同 XRV 初始化与相近训练来源也使 T1/F1c 可能共享偏差。读片器认证、编解码转移、噪声压力测试各覆盖不同问题，不能互相替代。【T1、T1v3、V1、S1；TRIBENCH_SPEC】

### EHR 诊断码与图像所见不是一回事

同一 EHR 记录了某个诊断，不保证当前胸片一定有清晰对应表现。设备复合标志、肺炎临床诊断、CHF 作为水肿代理尤其需要谨慎。生成图比真实图更贴合诊断标志，可能是过度执行条件，而不是更真实。【C1、V10、P3、P3b】

### 评测队列、参考分布与统计区间有边界

主要方法队列经过人口学平衡，不能直接等同于临床自然患病率。V8 用放射科阳性参考，V10 用同队列 EHR 阳性参考，V9 又使用代表年龄与不同编码参考，数值不能未经匹配就排名。早期独立抽样区间也不能改称配对区间；M3 的旧区间已由 v2 无放回协议替代，但正式统计表仍需说明样本数与区间含义。【C1、V8、V9、V10、M3 v2；TRIBENCH_SPEC】

### 真实 EHR 下的成功还没有完全迁移到用户规格

G1 未达完整规则；G1T 的纯文本减轻了年轻端压缩，但积液非请求阳性率仍偏高，文本还忽略了明确阴性。当前应优先用纯文本强基线解决条件语义，而不是继续把 token 的必要性当作前提。【G1、C2T、G1T】

### 三模态闭环不等于从零生成完整病例

P3/P3b 的 EHR 是真实留出记录，P1/G1 是人为构造的简化 EHR；完整 EHR 生成、纵向统计与复杂临床合理性尚未建立。高一致性也可能意味着把真实世界的不确定性过度清理掉。【P1、G1、P3、P3b】

### 人工读片和发布审批尚未完成

已有盲读包包含 48 张计分图以及 3 张练习图，但尚无医生回答和分析结果。现有计分组成是早期路线 A、C1 与真实图，不代表已经覆盖 C2/C2T 最新对照。是否补充新模型应由课题组与 PI 决定，不能自动把“包已就绪”写成“临床验证通过”。【reader_pkg docstring；README 读片包结果；rs_analyze docstring】

记忆化筛查也不替代数据使用、模型权重与图像分享的审批。本文仅讨论汇总信息；任何受保护材料的分享都应走既有项目与 PI 批准渠道。【C15、M2；README 读片包说明】

## 八 下一步计划与当前汇报建议

### 优先补足会改变方法选择的实验

G1T 现已完成，不再重复列为待做。它与 C2T 一起支持：优先以训练纯文本 C2T 为默认，保留混合 token 模型作为对照，避免为了复杂结构继续增加成本。【C2T、G1T】

下一步建议先补齐文字契约：明确阳性、明确阴性与 unknown 分开表达，让 FULL 与 MINIMAL 在应该不同的地方确实不同，再用同一规格与种子检验模型是否遵循。这个改进针对 renderer，不是修改 EHR 或把缺失补成阴性；效果尚待实验，本文没有执行代码修改。【G1T；TRIBENCH_SPEC】

再决定是否需要字段缺失增强。已有 C3 设计是从 C2 继续训练，通过字段缺失和 positives-only 扰动同时修改文字与 tokens，并要求既通过 G1 规格规则、又保留留出队列表现。既然新消融支持纯文本默认，应先由课题组决定是否修订训练起点与比较方案，而不是把已有 C3 设计当作已证实的最优方向。【C3 docstring；C2T、G1T】

### 把方法与评测做成一致的正式结果

- M3 v2 已重算；正式论文使用已披露的无放回协议，明确 FD 样本数与区间含义，不沿用旧 bootstrap 区间。【M3 v2；M3 docstring】
- 固定方法、读片器与主终点后，再进行独立确认，避免持续根据同一队列调指标或挑读片器。【T1v3、TRIBENCH_SPEC】
- 保留 C2T 强基线；对新用户规格路线补齐必要的校准、三模态和用途评测，而不是只追求二值高分。【C2T、V10、P3b、V5b】
- 新增 P4 已有三模态下游实验设计，拟复用 V5b 的 EHR 与图像生成报告，比较图像、EHR 及融合输入，并区分 EHR 已覆盖和未覆盖的 finding。它可以补足 V5b 主要检验图像用途的缺口；当前允许来源没有结果，不能宣称三模态下游有效，也不能推断作业状态。【P4 docstring】
- 收回盲读结果并按预定分析处理不确定答案；如需覆盖最新方法，先批准补充方案。【rs_analyze docstring】
- 若继续 Agent，优先证明在相同 EHR、预算可比、评分与选择尽可能分离时，定位和修复比固定路线或静态择优带来额外收益；同时报告真实调用成本、校准与多样性。【BENCHMARK_PLAN；CLAIMS】

### 当前可以如何向老师概括

> 图像与报告链路已经不只是 smoke test：我们有真实配对训练、纯文本消融、反事实编辑、三模态联合分布和部分下游正向证据。C2T 与新完成的 G1T 共同修正了故事——主要收益来自 EHR 落地的条件训练，不是 token 形式天然更好，当前纯文本是更简单的默认。接下来要解决的是用户规格的阴性与缺失语义、评分器鲁棒性、正式统计口径与医生评价；完整 synthetic EHR 和 Agent 的额外收益仍不能写成已完成。
